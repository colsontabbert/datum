# Tactile Web

**Tactile Web** is a web design style built around one core idea:

> Digital interfaces should feel like constructed objects, not abstract floating layers.

The style combines the hard structure of Web 1.0 and brutalism, the physicality of skeuomorphism (including raised and recessed controls), the restraint of Japanese minimalism, and the personality of webcore.

It should feel deliberately designed, tactile, personal, and slightly nostalgic without becoming a retro parody.

## Core influences

### 1. Web 1.0 structure

Use the early web as the structural foundation.

Favor:

- hard rectangular regions
- visible page sections
- obvious borders
- simple grids
- underlined links
- compact navigation
- native-looking controls when appropriate
- information-dense layouts
- interfaces that visibly reveal their structure

The page should feel built from actual pieces rather than floating cards.

Think early CERN, old documentation sites, directories, personal pages, and utility websites.

Do not imitate their technical limitations. Borrow their visual honesty.

---

### 2. Pure brutalism

Brutalism reinforces the structural side of the style.

Use:

- hard edges
- square or nearly square corners
- visible dividers
- strong alignment
- simple geometry
- black or dark structural lines
- straightforward typography
- little unnecessary ornament

The interface should make its construction obvious.

Avoid excessive softness.

A section should clearly begin and end.

A button should clearly be a button.

A window should clearly have a frame.

---

### 3. Skeuomorphic tactility

This is one of the most important parts of Tactile Web.

Certain interactive elements should suggest physical objects.

Examples:

- buttons that appear raised
- buttons that visibly depress when clicked
- recessed panels
- physical toggles
- mechanical switches
- sliders with visible tracks
- knobs
- LEDs
- small displays
- framed screens
- metallic, plastic, glass, rubber, or painted surfaces
- tabs that physically look selected or pushed inward

Use skeuomorphism selectively.

Not everything should resemble a physical object.

Text can simply be text.

Lists can simply be lists.

Navigation links can simply be links.

Physical styling should mainly emphasize interaction and hierarchy.

Use light and shadow deliberately so raised and recessed states feel physically understandable, not just decorative. A control should read as elevated, inset, pressed, or released the moment you look at it, a user should almost be able to imagine pushing it with a finger. Keep shadows and edges crisp rather than soft and blurred, that reads as brutalist and mechanical instead of squishy. Avoid the low-contrast gray-on-gray look that a purely soft-shadow treatment can fall into. Accessibility and legibility come first.

---

### 4. Japanese minimalism

Japanese minimalism acts as the restraint system for the entire style.

Without it, Tactile Web could easily become cluttered or kitschy.

Use:

- deliberate empty space
- restrained composition
- clear hierarchy
- careful alignment
- minimal decoration
- limited color palettes
- purposeful objects
- quiet typography
- balance between dense areas and open areas

Every object should have a reason to exist.

Do not decorate every surface just because decoration is available.

The interface should feel considered, not maximalist.

---

### 5. Webcore personality

Webcore adds human personality.

Use small amounts of:

- pixel graphics
- tiny custom icons
- unusual status indicators
- animated cursors or loading indicators
- stamps
- badges
- handmade graphics
- small GIF-like animations
- strange little decorative objects
- personal visual jokes
- intentionally non-standard details

The goal is to create the feeling that a specific person designed the site.

Avoid making every element polished into the same design-system language.

Small inconsistencies can be charming when deliberate.

---

# Overall balance

A useful mental model is:

**70% structure and restraint**

Web 1.0
brutalism
Japanese minimalism

**20% tactile interaction**

skeuomorphism
raised buttons
recessed controls
physical states

**10% personality**

webcore
custom graphics
small weird details

These are not literal percentages. They describe priority.

The interface should still work if all decorative styling is removed.

---

# Layout principles

Prefer layouts that feel constructed rather than floated.

Use:

- framed workspaces
- toolbars
- split panes
- sidebars
- status bars
- tab strips
- bordered sections
- visible column structures
- inset content areas
- control panels
- modular rectangular regions

Good inspiration includes:

- old desktop software
- technical equipment
- early websites
- operating-system utilities
- control panels
- manuals
- workstation software
- laboratory equipment

Avoid defaulting to modern landing-page structure.

Do not automatically create:

- giant centered hero sections
- floating feature cards
- bento grids
- repeated rounded cards
- testimonial strips
- logo clouds
- endless CTA sections

---

# Shape language

Default shape:

**rectangle**

Secondary shapes:

- slightly beveled rectangle
- inset panel
- physical button
- tab
- display
- indicator light
- small circle for functional controls

Use rounded corners sparingly.

Do not use large border radii as the default.

A control may be rounded if its physical reference would naturally be rounded.

---

# Typography

Typography should be functional and slightly characterful.

Good combinations include:

- clean sans serif for interface text
- monospace for system information
- occasional serif for editorial or atmospheric content
- bitmap or pixel fonts only in small doses

Typography should communicate hierarchy through:

- size
- weight
- spacing
- alignment
- capitalization
- placement

Do not rely on giant marketing headlines to create visual interest.

---

# Color

Base colors should usually remain restrained.

Possible foundations:

- warm white
- light gray
- beige
- pale blue
- muted green
- dark charcoal
- black

Accent colors can pull from old computing and utilitarian interfaces:

- clear blue
- grass green
- aqua
- cyan
- orange
- red
- amber

Use bright colors functionally.

Examples:

- green for active
- amber for waiting
- red for warnings
- blue for links
- cyan for secondary system information

Avoid the default modern startup palette of purple-blue gradients.

---

# Materials

When physical texture is appropriate, think in materials.

Possible UI materials:

- matte plastic
- translucent plastic
- brushed metal
- painted metal
- glass
- rubber
- paper
- CRT glass
- molded plastic
- soft-touch plastic

Different components may have different materials if the distinction communicates function.

Do not texture everything.

---

# Interaction

Interaction is extremely important to Tactile Web.

Controls should visibly react.

For example:

Button idle:
raised

Button hover:
no visual change, feedback is reserved for the press itself

Button pressed:
edges invert, reads as recessed rather than raised

Toggle:
physically travels between states

Tab:
selected tab appears connected to its content panel

Slider:
thumb visibly sits on a track

Panel:
selected or active state may become slightly recessed

The user should receive immediate physical-looking feedback.

---

# Motion

Prefer small mechanical motion over large cinematic motion.

Good:

- button depression
- switches moving
- LEDs blinking
- trays sliding
- panels opening
- tabs snapping into place
- tiny loading animations
- progress bars
- cursor reactions

Avoid:

- constant floating
- giant parallax scenes
- blobs drifting around
- every object slowly bobbing
- excessive scroll-triggered animation

Motion should communicate state.

---

# Icons

Avoid relying entirely on generic modern icon libraries.

Use a mixture of:

- simple system icons
- custom bitmap icons
- small skeuomorphic icons
- symbolic technical icons
- familiar UI glyphs

Custom icons are encouraged when they contribute personality.

Specific preference: old, nostalgic, pixelated icons, the chunky low-resolution look of Windows 98-era system icons, are the default direction for custom icon work, not a stylistic option among several. Where a custom icon is warranted, reach for that look first.

Do not make every feature card a Lucide icon above a heading.

---

# Personality

Tactile Web should feel:

- functional
- curious
- personal
- mechanical
- slightly nostalgic
- human-made
- playful in small ways
- understandable
- visually memorable

It should not feel:

- sterile
- corporate
- over-polished
- futuristic for its own sake
- luxury-minimalist
- crypto-like
- AI-generated
- template-driven

---

# Anti-patterns

Avoid these unless specifically requested:

- giant purple or blue gradient blobs
- glassmorphism everywhere
- bento feature grids
- pill-shaped labels everywhere
- excessive rounded corners
- giant centered SaaS hero sections
- floating dashboard screenshots
- generic Lucide icon grids
- gradients used without purpose
- dark navy startup backgrounds
- abstract glowing spheres
- meaningless 3D objects
- huge empty sections pretending to be premium
- identical cards repeated down the page
- overly smooth animation
- generic AI illustrations
- fake Frutiger Aero-style bubble/chrome/glass imagery
- everything being contained inside a card

A page should not look like it was assembled from a standard React SaaS template.

---

# Core design test

When designing any component, ask:

### 1. What is this object?

Is it a panel, switch, button, document, display, tab, list, window, dial, or something else?

### 2. How is it constructed?

Does it have an edge, frame, surface, track, hinge, recess, or border?

### 3. How does the user interact with it?

Can it be pushed, dragged, selected, opened, moved, toggled, or typed into?

### 4. What physical feedback should that interaction imply?

Pressed, raised, lit, recessed, switched, opened, or selected?

### 5. Does it actually need decoration?

If not, leave it alone.

---

# Most important rule

Do not begin by thinking in modern frontend components.

Do not start with:

navbar
hero
card
card
card
CTA

Start with:

information hierarchy
workspace structure
physical metaphor
interaction
materials
typography
spacing
personality

Then implement the components required by that design.

---

# Short prompt version

When asked to build something in the Tactile Web style, interpret that as:

> Build a restrained, tactile interface combining Web 1.0 blockiness, pure brutalist structure, Japanese minimalism, selective skeuomorphic controls with raised and recessed states, and small amounts of personal webcore detail.
>
> Use hard rectangular layouts, visible borders, framed workspaces, physical-looking controls, deliberate whitespace, custom small details, and clearly differentiated interaction states.
>
> Avoid modern SaaS design conventions including bento grids, excessive rounded cards, pill badges, purple-blue gradients, generic icon grids, floating glass panels, oversized centered heroes, and other template-like AI frontend patterns.
>
> The interface should feel like a thoughtfully designed physical workstation that happens to exist inside a browser.
